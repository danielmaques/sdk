# SDK diagnostics contract

`pushify.sdk-diagnostics/v1` is opt-in local debug output. The bundled Inspector views enable collection while visible and disable it when closed or unmounted; host apps may also control the debug API directly. Event names are `sdk_configured`, `customer_info_requested`, `offerings_requested`, `purchase_started`, `purchase_completed`, `restore_completed`, and `request_failed`. Each event carries a UTC epoch-millisecond timestamp, UUID correlation ID, outcome, retryable flag, and a fixed safe message. Ring buffers keep at most 100 events in memory.

Exports may include platform, API host, a masked public key, counts of cached offerings, products, and active entitlements, `retry_queue_count`, and `recent_retryable_failure_count` (retryable failures still present in the bounded in-memory event buffer). `retry_queue_count` counts StoreKit unfinished transactions on iOS and purchased, unacknowledged Play purchases on Android; it is `null` until the platform query completes or if the query is unavailable. It is a current store queue snapshot, not a count of the SDK's bounded event buffer. Exports must not include customer IDs, attributes, receipt data, transaction IDs, purchase tokens, server response bodies, request paths, or credentials. Applications must explicitly enable the inspector; SDK diagnostics never upload automatically.
