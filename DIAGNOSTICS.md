# SDK diagnostics contract

`pushify.sdk-diagnostics/v1` is opt-in local debug output. The bundled Inspector views enable collection while visible and disable it when closed or unmounted; host apps may also control the debug API directly. Event names include `sdk_configured`, `customer_info_requested`, `offerings_requested`, `purchase_started`, `purchase_completed`, `restore_completed`, `entitlement_sync_completed`, and `request_failed`. Each event carries a UTC epoch-millisecond timestamp, UUID correlation ID, outcome, retryable flag, and a fixed safe message. Ring buffers keep at most 100 events in memory.

Exports include platform, API host, SDK version, app version when supplied or available from the host, build environment, a privacy-safe customer state (`cached` or `not_loaded`), masked public key, cached offering and product IDs, active entitlement count, local store product resolution counts, and last offerings/sync outcomes with timestamps and correlation IDs. `retry_queue_count` and store product counts are `null` when not yet checked or unavailable. The retry queue counts StoreKit unfinished transactions on iOS and purchased, unacknowledged Play purchases on Android; it is a current store queue snapshot, not a count of the SDK's bounded event buffer. `recent_retryable_failure_count` counts retryable failures still present in the bounded event buffer. Flutter and React Native accept an optional app version in their SDK configuration; native SDKs read the host app version from platform metadata. Exports must not include customer IDs, attributes, receipt data, transaction IDs, purchase tokens, server response bodies, request paths, or credentials. Applications must explicitly enable the inspector; SDK diagnostics never upload automatically.
